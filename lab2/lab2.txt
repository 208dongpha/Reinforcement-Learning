BỔ SUNG GIẢI THÍCH
1) Định nghĩa Q-table
- Q-table là bảng giá trị hành động: kích thước |S| x |A|.
- Mỗi phần tử Q(s,a) là giá trị kỳ vọng của tổng reward có chiết khấu khi ở trạng thái s, chọn hành động a, rồi làm theo policy tối ưu.

2) Value iteration cho action value được tính như thế nào?
- Với mỗi state s và action a, ta ước lượng:
  Q(s,a) = E[ r + gamma * max_{a'} Q(s', a') ]
- Đây là Bellman optimality cho Q-value: lấy reward tức thời r cộng với giá trị tốt nhất ở trạng thái kế tiếp.

3) Giải thích công thức cập nhật trong code
Q[state, action] = old_value + alpha * ( reward + gamma * max(Q[next_state]) - old_value )
- old_value: giá trị Q hiện tại.
- reward + gamma * max(Q[next_state]): mục tiêu TD (TD target).
- (target - old_value): sai số TD (TD error).
- alpha: learning rate, quyết định cập nhật nhanh hay chậm.
=> Q-learning là off-policy vì dùng max(Q[next_state]) (hành động tối ưu giả định).

4) Bản đồ 16 ô, Q-table 16 dòng x 4 cột nghĩa là gì?
- FrozenLake 4x4 có 16 state (0..15), nên Q-table có 16 dòng.
- Mỗi dòng có 4 cột cho 4 hành động (LEFT, DOWN, RIGHT, UP theo thứ tự mặc định của Gym).
- Giá trị Q không phải reward ngay lập tức, mà là kỳ vọng tổng reward về sau.
- Reward tức thời được lấy từ môi trường:
  +1 khi tới GOAL, còn lại thường là 0 (kể cả khi rơi hố).
- Q(s,a) tăng dần khi nhiều lần chọn a từ s dẫn tới trạng thái tốt hơn.

5) Cách suy ra bước đi (policy) từ Q-table
- Dùng greedy policy: a* = argmax_a Q(s,a).
- Bắt đầu từ state 0, lặp:
  1) Chọn a* theo Q.
  2) Thực hiện action trong môi trường để lấy state tiếp theo.
  3) Lặp tới khi done (GOAL hoặc HOLE).
- Nếu cần ánh xạ state -> (row, col): row = s // 4, col = s % 4.
  => Dựa vào đó có thể vẽ đường đi trên bản đồ.
